# SKU Code 自动生成参考

当你需要为 catalog 自动生成 `sku_code` 时，必须先遵循本文档，再调用
`node dist/scripts/run_skill.js --skill catalog`。

## 推荐模板

优先使用下面的结构生成：

`[品牌缩写]-[类目缩写]-[商品款号]-[属性1]-[属性2]`

示例：

- `NK-TS-1024-WHT-L`

含义：

- `NK`：品牌缩写，例如 Nike
- `TS`：类目缩写，例如 T-Shirt
- `1024`：内部款号 / 型号
- `WHT`：属性 1，例如 White
- `L`：属性 2，例如尺码

## 生成规则

1. `sku_code` 必须永久唯一，不得复用给未来的新商品。
2. 只允许使用大写字母、数字、连字符 `-`、下划线 `_`。
3. 总长度建议控制在 30 个字符以内。
4. 生成时尽量避开容易混淆的字符：
   - `O` / `0`
   - `I` / `l` / `1`
5. 预留扩展性，不要把未来可能新增的属性编码死在当前规则里。

## Best-Effort 生成顺序

1. 优先使用品牌、类目、款号、关键属性来拼接。
2. 如果部分字段缺失，先建议用户补充。
3. 如果用户没有更多信息，就使用现有字段继续生成。
4. 如果仍然无法按模板稳定生成，再退化到基于标题的默认编码版本。

## 你对用户的说明义务

在自动生成 `sku_code` 前，你必须：

1. 先告诉用户会使用什么生成标准。
2. 至少举一个示例。
3. 生成出候选 `sku_code` 后，明确告诉用户最终将要创建的编码。

## 调用前检查

在调用 runtime 前，你应确保最终 `sku_code`：

- 已转成大写
- 不包含空格和中文
- 不包含 `&`、`*`、`@` 等特殊字符
- 尽量可读且可扩展

runtime 只负责：

- 校验格式
- 校验唯一性
- 写入数据库

runtime 不负责生成 `sku_code`。
